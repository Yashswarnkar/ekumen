## SUMMARY

- **Planner (`internal/core/plan.go`).** Pure and closed: after its events are written, planning again plans nothing. Stages run in order: default → apply → route → conflict. Each stage is a plain method, so rule evaluation can later be one more stage.

  - **Apply:** plans against the state with this pass's defaults reduced in.
  - **Route:** whatever `core.Route` returns over the whole log.
  - **Conflict:** a tier-2 decision (unless already raised), then `ConflictDetected` on that decision.
  - **Report:** `ready`, `not_startable`, `unblocked`, `notify`. The loop never starts sessions and never writes `TaskSessionAttached`.
- **Executor (`internal/cli/reconcile.go`).**
  - It runs as `loop:<session>` only; every other role is refused with exit 2.
  - It loads and observes once.
  - Each action is its own all-or-none write. After writing, the action is absorbed into the snapshot, so later actions are admitted against it. Projections are written once, at the end.
  - A failure partway exits 5 and names the events already recorded.
  - Exit is 0 when the pass recorded conflicts.

## DEVIATIONS

- **Planner signature.** The brief suggested `Plan(s *State, obs, now, in) Plan`. I built `core.PlanPass(PlanInput) (Plan, error)`, because `Plan` is the result type's name and the planner needs the events, not just the state: routing, lane checks and re-reducing between stages all read the log. `PlanInput` also carries the loop actor and an id function, so the dry run shows the same event ids a real pass would write. The error is only an id-generation or validation failure.
- **Conflict decision id suffix.** I used the **last** 6 characters of the lowest event id (lowercased), not the first. A ULID's first 6 characters are the high bits of its timestamp (about a 4.4-minute window), so two conflicts of one rule from one merge or import would collide. The last characters are random. If the id is taken by a different conflict's decision (compared by `context.evidence`), the suffix grows to 8, then 10.
- **ConflictDetected subject.** I put it on the conflict's decision, so it sorts after that decision's `DecisionRaised` in the subject's lifecycle.
- **Extra report fields beyond the suggested shape:**
  - `detail` per action;
  - `planned` (dry run only);
  - `orchestrator_actions`.
- **Planned `TaskAmended` in a dry run** have an empty `file` and `text_sha256`. Both are known only once the file is written.
- **PR #19 size.** It is about 890 changed lines with tests, over the brief's ~600. The planner and its six tests didn't split coherently.
