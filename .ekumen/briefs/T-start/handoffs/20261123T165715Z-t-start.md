## OUTPUT

- `ekumen init [--project] [--lead]`, `ekumen task start <id> [--open] [--agent] [--setup]`, `ekumen task start --list`, as specified in docs/cli.md "Setup commands".
- On this repo, `ekumen task start --list` today shows T-audit (its worktree `.worktrees/t-audit` doesn't exist).
- Choices made inside the brief:
  - Worktree paths resolve against the project's folder in the **main** working tree (`git rev-parse --git-common-dir`), so running it from a task worktree doesn't nest worktrees.
  - New branches are created with `--no-track`, so a session's `git push` can't target the base branch.
  - `git fetch origin <base>` runs before creating a branch; a failed fetch is a warning.
  - Setup runs only in a newly created worktree (or with `--setup`), so a repeat run changes nothing. A dirty worktree gets a warning and no setup, but the command is still printed, so the lead can reopen a session that already has work.
  - "Attached already" means a `TaskSessionAttached` event for the recorded session exists; a session named only at draft time gets attached, with the agent name as adapter.
  - An empty `session` is a refusal reason (fix: `ekumen task attach <id> --session …`); no name is invented.
  - The agent command's first word, when bare, is resolved to an absolute path on PATH (C-adapter §6: never an alias).
  - The command sets `EKUMEN_ACTOR=session:<s>` for the agent process as well as naming it in the prompt.
  - `init` creates `events/` without a `.gitkeep`, because `check` rejects any non-subject-kind entry in `events/`.
