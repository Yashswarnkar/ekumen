## FRICTION

- **Lead's handle (`decision answer` as `lead:<handle>`):** no `--json` read prints it, though `project.Snapshot.Lead()` computes it (config.yaml `lead:`, else the latest lead actor). `/decide` falls back to `EKUMEN_ACTOR` or asking the lead once. Candidate: `lead` in `status --json`.
- **`decision apply --json` result:** prints only the write shape, so the skill needs a second read (`decision show`) for `applied.unblocked_tasks`; the human output has the counts but not the ids.
- **Session notification with no adapter:** both skills print "send this line to session X" for the lead to paste (C-adapter §3 fallback). There is no `MessageQueued` record, so nothing shows the lead which sessions still need telling; `applied.notified_sessions` is always `[]`.
- **Finding a blocked task's session:** `/decide` must run `task show <task> --json` per task in `blocks` to get `task.session`. A `sessions` (or `blocks` with sessions) field on the decision view would save the calls.
- **Placeholder task record:** `task show T-skills --json` has `branch: null`, `brief: null` and status `blocked`/`approved` rather than `ready`/`running` (D-placeholder-task-fields). `/blocked` only needs `tier_grants`, which is correct, so no workaround was needed, but an agent reading `task.brief`/`task.branch` would be misled.
- **`task show --json` size:** it returns all of `brief.text` (~20 KB for this brief) every time a skill only wants `tier_grants` or `brief.amendments`. A `--no-text` flag or an `amendments`-only read would cut tokens on every `/blocked` check.
- **Actor spelling inconsistency:** `decision.decided_by` is the bare id (`Yashswarnkar`) while `questions[].by`/`answered_by` are `<role>:<id>` (`lead:Yashswarnkar`), and an amendment entry's `author` is `loop:t-skills` while its file front matter says `author: t-skills`. Skills that compare actors have to normalise.
- **Duplicate detection (`decision list --status pending`):** there is no filter by task or text, so `/blocked` asks the agent to scan every pending decision's title by judgment. A `--blocks <task>` filter would make the common case code.
- **Ambiguity, Agent Skills format vs invariant 12:** none found; the format's required keys are vendor-neutral. The only vendor names are in the `docs/skills.md` folder table, as §A asks.
- **Ambiguity, C-cli-json:** `skills install` is neither a read nor a lane-based write, so it fits neither §2 nor §3; the proposed text adds a §3a for commands with no actor.
