## SUMMARY

1. **D-imported-event-time-order.** `core.SortEvents` orders each subject's events by lifecycle step (`LifecycleRank`), then by ULID time. It then merges the subjects by time, using a heap that always takes the earliest next event. Project-wide events (role claims, spine approvals) keep plain time order, so claim → release → claim still works. New rule `orphan-step` (`core.OrphanStepConflicts`) covers:
   - item events with no creating event;
   - `DecisionApplied` with no decide or default;
   - `QuestionAnswered` with no ask.
   `decision apply` now refuses to record an apply that would not take effect.
2. **D-projections-in-git.** `.ekumen/registry.yaml` and `.ekumen/state.json` are git-ignored and removed from the index. A fresh clone runs status, inbox, task list, graph, check, map and `project --check` without them. The project name now comes from the `origin` remote, then from a local registry, then from the folder name. New command `ekumen project --check` (`Snapshot.CheckProjections`) fails when a committed `decisions/<id>.yaml` is stale or missing, or names no decision in the log. `scripts/ci-check.sh` runs it after `check`.
3. **D-contract-version-recording.** New command `ekumen contract version <id> --by <decision>` (orchestrator) records `ContractVersioned`. A recorded version no longer marks the contract frozen: it becomes `Contract.Pending` and waits for `contract freeze`. `frozen-text-changed` compares against the highest `ContractFrozen` and accepts the pending text.
4. **D-post-switch-hand-edits.** The owner-edited prose files are listed in `docs/cli.md` ("Owner-edited prose files"). New command `ekumen spine approve` (lead) records `SpineApproved {text_sha256}` on subject `project`. New rule `spine-unapproved`.
5. **D-apply-amend-lane.** `TaskAmended.by_decision` is new. The loop may write `TaskAmended` only when `by_decision` is set (`Lane.ByDecision`). `decision apply` writes everything as `loop:<id>` and needs no orchestrator claim.
6. **Audit findings.**
   - `check` reports `orphan-entry` for amendment and handoff files that no event records.
   - `inbox --for lead` adds items of kind `action` (`core.LeadActions`), each with an `action` (approve, freeze or apply) and a `command`.
7. **Map fragment.** `ekumen map --fragment` writes the page without its document wrappers, with styles scoped to `<div class="ekumen-map">`.
8. **Map links (amendment).** `ekumen map` links each item to its source file: decisions to their YAML, tasks to their brief and latest handoff, contracts to their body, and PRs to the PR. `mapview.LinkBase` builds the base URL. GitHub (`git@`, `ssh://` and `https(.git)` remotes) is the only built-in host, and `--link-base` overrides it. There are no links without a remote. Golden tests cover the no-remote, GitHub and unknown-host cases.

Tests are named after their decision ids, for example `TestCausalOrderWithinSubject_DImportedEventTimeOrder` and `TestProjectCheck_DProjectionsInGit`. Items 6–8 are named after their audit finding or job number.

## DEVIATIONS

- **Inbox order for the lead.** Decisions come first, then conflicts, then actions, then routes. The brief says actions "rank after decisions", and I kept conflicts ahead of actions.
- **`orphan-entry` is reported under `invalid` (exit 2), not `conflicts`.** It concerns a file with no event, and a `Conflict` needs event ids.
- **`contract freeze` is stricter.** It refuses a higher version of an already-frozen contract unless `contract version` recorded that version with that text. This enforces the protocol the decision chose. Freezing a draft contract works as before.
- **`ContractVersioned` alone no longer makes a contract frozen.** This is a reducer change. The real log has no `ContractVersioned` events, so nothing changes there.
- **`spine-unapproved` is not reported before the first `SpineApproved`.** Otherwise CI would fail until the lead approves.
- **"Older than a day"** is measured from the decide or default event's time (its ULID), using `core.ApplyAfter` = 24h.

## FRICTION

1. One `contract version --by` takes a single decision, but C-event-log v5 bundles five decisions. The event has no place for the other four (see FOLLOW-UPS).
2. "Older than a day" and "rank after decisions" needed interpretation (see DEVIATIONS).
3. Ordering uses the ULID's time, not the envelope's `at`. The two can differ, and C-event-log doesn't say which one is authoritative.
4. My first fragment test searched for `<head`, which also matches the page's `<header>`. Checking for "no `<head>`" needs an exact-tag test.
5. In a zsh `for` loop, `bin/ekumen $c` does not word-split, so the first fresh-clone check gave false failures until I used `eval`. This is the same zsh friction as in earlier handoffs.
6. To reproduce the bug I had to build the old binary from `git archive HEAD` (stash left untracked files behind). An `ekumen check --at <commit>` or a documented scratch-copy recipe would help auditors.
