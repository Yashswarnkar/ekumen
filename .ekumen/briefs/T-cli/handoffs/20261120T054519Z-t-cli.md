# T-cli handoff

## STATUS

Done, in review (draft PR). Every C-cli-json v1 command is implemented with `--json`, plus `ekumen project`. Built against C-event-log v3, C-decision-record v2 and C-cli-json v1 on main at 3f695f3. `go test -race ./...`, `go vet ./...` and `gofmt -l .` are clean, and a manual end-to-end run against a temp project with the built binary passed. Four decision drafts below; the code implements the recommended option for each, so nothing is blocked.

## OUTPUT

- `internal/cli/`: argument parsing (standard library `flag`, with flags and positionals in any order), project root, actor (`--as` / `EKUMEN_ACTOR`), `--json`, exit codes and the error shape (C-cli-json §1). Read commands are in `read.go`, write commands in `write.go`, and YAML input plus handoff parsing in `input.go`. A write checks the lane first, then validates, then appends; it records all of its events or none, and an amendment or handoff file is removed again if its event can't be recorded.
- `internal/project/`: `Snapshot` (events + `core.Reduce` + observations), the C-cli-json §4 views, the v3 lane checks where core lags (`lanes.go`), and the projections `decisions/<id>.yaml`, `registry.yaml` and `state.json`. These are regenerated after every write and by `ekumen project`. Projections are skipped on an empty log, so they can't wipe today's hand-written records before T-import runs.
- `internal/observe/`: PRs from `gh pr list`, behind an `Observer` interface. Tests use `observe.Static`. Without `gh`, `observed` is `null` and a warning goes to stderr; `EKUMEN_OBSERVE=off` turns observation off.
- `internal/mapview/`: `ekumen map`, a Go port of `tools/map-prototype`. It renders the data from `graph`, `inbox --for lead`, tasks and decisions. dagre 0.8.5 is inlined from `assets/dagre.min.js` (from cdnjs, sha256 62eb9787…cd51), its MIT license is in `assets/dagre.LICENSE`, and the Google Fonts link is gone. The page makes no network requests; I checked it with headless Chrome.
- `docs/cli.md`: an example for every command.
- Tests: golden `--json` output for every read command plus the projections against a fixture project built through the CLI (`internal/cli/testdata/golden/`, refresh with `go test ./internal/cli -update`); exit codes and error codes/fields; lane refusals, which leave no events or files behind; `check` finding `lane`, `decided-twice` and `frozen-text-changed`; and an end-to-end test (raise → question → answer → amend → handoff → status → route resolve → check → map).
- `go.mod`: `go.yaml.in/yaml/v3 v3.0.6` (D-yaml-library). There are no other dependencies.

## FOLLOW-UPS

- Core lags C-event-log v3 (worked around in `internal/project`, not fixed in core):
  - `core.Lanes` still has DecisionRaised as session/integrator only; v3 also lets the lead, orchestrator and loop raise.
  - RouteResolved is still orchestrator-only; v3 lets the route's owner resolve it.
  - RoleClaimed/RoleReleased are loop-only (see D-claim-lane).
  - `event.TaskDrafted` has no `session` field, so `SessionTasks` ignores it. The CLI writes it as an extra field and applies it after `Reduce` (`Snapshot.attachDraftSessions`).
- `core.Reduce` drops a RouteResolved that has no RoutedToOwner yet. Until the loop exists, the CLI computes pending routes with `core.Route` and closes them from RouteResolved events itself (`Snapshot.Routes`). T-reconcile should write RoutedToOwner for those, or core should keep early resolutions.
- `files.Store.WriteEntry` reads its own clock, so an entry's file-name timestamp and its event's `at` can differ by a second, and tests can't fix the name. Add a time parameter.
- `core.Question.By`, `AnsweredBy` and `Decision.DecidedBy` are actor ids only. The CLI looks up the role from the event to print `role:id`, except for `decided_by`, which stays the bare id as in the hand-written records.
- `.github/workflows/ci.yml` still says "stdlib only: no go.sum". There is a go.sum now, so the Go cache could be turned on.
- `tools/map-prototype/` can be deleted (its README says so once `ekumen map` ships). I left it alone because it is outside my brief.
- T-import: the CLI reads the TaskDrafted `session` extra field, brief and contract paths relative to either `.ekumen/` or the repo root, and the contract's front-matter `version`.

## DEVIATIONS

1. Minor additions (C-cli-json §5): `Task.brief`, `InboxItem.subject`, `url` and `title` on the observed PR, `--note` on `task amend`, `ekumen help`, `EKUMEN_OBSERVE=off`.
2. Inboxes include routes the loop would write (`core.Route`) and, for the lead, unrecorded conflicts (`kind: conflict`) after the ranked decisions.
3. `check` exits 2 when files are invalid but nothing conflicts. The contract only defines exit 4 for conflicts.
4. `decision raise` refuses unknown top-level fields and fills in a missing `raised_by` from the actor.
5. Question ids are `q-` plus the lowercased ULID of the asking event, so they are unique across subjects and branches.
6. `ekumen` with no arguments exits 1 (usage) rather than the scaffold's 2.

## FRICTION

- **Using the CLI on itself:** `ekumen --as session:t-cli task handoff T-cli --text-file …` against this repo exits **3 (not_found: no task "T-cli")**, not the lane refusal the amendment predicted. The log is empty until T-import runs, so the task doesn't exist yet. I wrote this file by hand. Before I added a warning, `ekumen status` here printed an empty project with no hint why. It now warns that the event log is empty.
- The decided-but-not-applied gate (D-apply-before-loop) will be the first thing the orchestrator hits after the switch.
- Two path conventions: event `file` fields are relative to `.ekumen/` (`Store.Rel`), but C-cli-json output paths and the core test data use `.ekumen/...`. The CLI accepts both. The contract should name one.
- C-cli-json shows `to: "session:t-core"`, but core compares `to` with a bare role or session name. The CLI stores the bare form and prints `session:<name>`.
- Question ids are long to type. Prefix matching would help.
- Handoff front matter (task, author, date) is still undefined. The parser ignores it and needs a `## STATUS` section.
- The project name comes from `registry.yaml`'s `project` field, or else the folder name. In a worktree without a registry that would be `t-cli`. A `project` field somewhere authoritative would help.
