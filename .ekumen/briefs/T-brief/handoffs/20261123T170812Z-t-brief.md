## SUMMARY

1. **`ekumen brief new <id> --title t [--kind] [--blocked-by] [--grants] [--from-issue N]`** (orchestrator lane, `internal/cli/brief.go`):
   - writes `.ekumen/briefs/<id>/brief.md` from `.ekumen/templates/brief.md`, or from the built-in `internal/cli/brief_template.md`;
   - records `TaskDrafted` in the same write, and removes the file if the event fails;
   - defaults: session `<id lower>`, branch `build/<id lower>`, worktree `.worktrees/<id lower>`, base branch from `origin/HEAD` (else `main`), repo = project name. Each can be overridden with a flag;
   - validation is shared with `task draft` (I extracted `taskDraftEvent`). A reused id and an existing `brief.md` are refused;
   - `--from-issue N` runs `gh issue view N --json number,title,body,url` and fills the Goal with "GitHub **#N**: [title](url)" plus the quoted body. Without `--title`, the task takes the issue's title. If `gh` is missing or fails: a warning, and the Goal keeps its hint.
2. **`ekumen brief check <id>`**:
   - the pure validator is `core.CheckBrief` (`internal/core/brief.go`);
   - it checks front matter (id, title, kind, `blocked_by` ids recorded) and the eight sections, each present once and filled: not empty, no `TODO(brief)` hint, not unchanged from the template;
   - it requires a checkbox in the DoD, and a Start prompt that sets the actor and names `task handoff`;
   - exit 2 with `problems: [{section, message}]`.
3. **`ekumen check`** runs it on every drafted, unapproved, undeferred task that has a brief. Problems go under a new `briefs` field and are **reported, never failed on** (the lead's decision in this terminal, see DECISIONS RAISED).
4. **`/brief` skill** (`skills/brief/SKILL.md`), embedded and installable; `skills list` shows it. It covers the spine and issue, verifying against main, scaffolding, section-by-section guidance taken from T-inbox-v1/T-start/T-brief, `brief check`, and the report to the lead. It never approves.
5. **Inbox:** the orchestrator's `brief` action command is now `ekumen brief new <id> --existing`. The reason names the path and the `/brief` skill.
6. **Docs:** `docs/cli.md` (`brief new`, `brief check`, `check`'s `briefs` field, the inbox table) and `docs/skills.md`.
