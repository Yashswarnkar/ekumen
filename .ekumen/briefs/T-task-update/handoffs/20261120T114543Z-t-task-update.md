## DEVIATIONS

- The brief says "validate the same formats as TaskDrafted (branch and path rules)". TaskDrafted has no such checks today, so `task update` adds its own: git branch-name rules for `branch`/`base_branch`, relative in-repo path for `worktree`, `ResolvePath` (inside `.ekumen/`) for `brief`, no whitespace in `repo`. `task draft` is unchanged.
- `pending_update` shows `current` values next to the proposed `fields` rather than adding `repo`, `base_branch` and `worktree` to every Task, which would have churned every task golden.
- The approve action for a pending update ignores open blockers (unlike the approve-draft action): an update to a blocked task is still the lead's to accept.
- The map golden runs the page script under node (as the existing two-fragments test does) and is skipped without node; CI's UI job has node.

## FRICTION

- The brief expects `task list` to show `ready` after the dogfood approval; in the real repo both tasks already have PRs (T-skills merged, T-reconcile draft), so they derive `done` and `running`. Briefs that predict status for tasks with live PRs go stale quickly.
- With `EKUMEN_OBSERVE=off` nearly every task is `blocked` (blockers are done only by observed PRs), which makes observation-off dogfooding less useful than it looks.
- Re-approval re-records `tier_grants` from the current ones unless `--grants` is passed; the lead can't tell from the inbox line that approving also re-confirms grants. Fine for now, but worth a word in the decide skill.
- No `contract list` yet, so finding a contract's id still means `graph` or `registry.yaml` (out of scope here).
