## OUTPUT

- **Aliases (v3 §1).** `event.ValidateAlias` now checks only that an alias is a non-empty string without `/` or whitespace. Whether an alias is already an id in use is checked against state by `core.ValidateDecision` (rule 7), so `D-001`…`D-019` are accepted.
- **Payloads.** `TaskDrafted` gains an optional `session`. `ContractDrafted` gains an optional `blocked_by[]`. There is a new `ContractBlockersChanged {added, removed, reason}` event (26 types). `TaskDrafted`'s JSON field order is unchanged, so the import's event ids for tasks are unchanged.
- **Lanes v4 (§3).**
  - `DecisionRaised` can be written by the lead, orchestrator, session, integrator or loop. The own-task check applies only to sessions and integrators.
  - `TaskSessionAttached` can be written by the orchestrator or the loop.
  - `ContractBlockersChanged` can be written by the orchestrator.
  - `RouteResolved` can be written by the route's owner (`State.RouteOwner`). This covers routes the loop has not written yet.
  - `RoleClaimed` and `RoleReleased` must have `data.session` equal to the actor (D-claim-lane).
  - A session's own tasks (`SessionTasks`) are those whose `TaskDrafted.session` names it, plus those whose latest `TaskSessionAttached` names it. `Task.Session` is the latest attachment, or else the drafted session. `Task.DraftSession` is new.
- **Contract blockers (D-contract-blockers).** A contract clears a task only when it is frozen and `ContractOpenBlockers` is empty. A cycle counts as open. `BlockedByDecision` (and so `Priority`) reaches tasks through contracts' `blocked_by`, transitively.
- **Same-timestamp order (v4 §2).** `SortEvents` sorts by the ULID millisecond, then `LifecycleRank`, then id. It does not depend on ULID entropy. The rank table is in `internal/core/README.md`.
- **Early route resolutions.** `Reduce` keeps a `RouteResolved` that arrives before its `RoutedToOwner` in `State.EarlyResolutions`, and closes the route when the `RoutedToOwner` appears.
- **File store.** `WriteBrief(task, text)` creates the file and never overwrites; it returns `fs.ErrExist` if the file is there. `WriteEntryAt(task, kind, author, at, body)` uses the same naming and `-N` clash rule as `WriteEntry`, which now calls it.
- **Workarounds removed.**
  - `internal/project`: `Snapshot.attachDraftSessions` and the v3 lane re-check in `Snapshot.Conflicts` are gone. `Snapshot.CheckLane` is now just `core.CheckLaneIn`. `Snapshot.Routes` uses `State.EarlyResolutions` instead of scanning events. The unused `Matches` is gone.
  - `internal/legacyimport`:
    - It no longer writes the 9 synthetic `loop:loop` `TaskSessionAttached` events.
    - Contract `blocked_by` is now a real field rather than `legacy` data. Verification now compares it.
    - The `core_lag_*` sections are gone.
    - `Apply` writes briefs and entries through `WriteBrief` and `WriteEntryAt`, and checks that each file lands at its planned name.
- **Tests, named after contract sections:** `TestValidateAlias_EventLog1Aliases`, `TestLaneTable_EventLog3`, `TestLaneClaimingSession_EventLog3`, `TestLaneDecisionRaisers_EventLog3`, `TestLaneOwnTaskSources_EventLog3`, `TestLaneRouteResolved_EventLog3`, `TestSameTimestampLifecycleOrder_EventLog2`, `TestEarlyRouteResolution_EventLog4`, `TestContractBlockers_EventLog6`, `TestWriteEntryAt_EventLog8`, `TestWriteBrief_EventLog8`, plus alias cases in `TestValidateDecision_DecisionRecord2`.

  - In the import's `events.golden.jsonl`, 7 `TaskSessionAttached` lines are gone, and 3 `ContractDrafted` lines now carry `blocked_by`.
